# project-review スキル

> **使うタイミング**: コミット前・PR 作成前。
> 公式 `/review`（PR 全体のアーキテクチャレビュー）とは役割が異なる。

## ステップ 1 — 自動チェック

```bash
npm run test:run       # テスト全通過
npm run test:coverage  # カバレッジ 80% 以上
npx tsc --noEmit      # 型エラーなし
npm run lint          # Lint クリーン
```

## ステップ 2 — TDD 準拠

- [ ] 変更した実装ファイルに対応するテストファイルが存在する
- [ ] テストがカバレッジ閾値（80% 以上）を維持している
- [ ] テストの説明が **日本語・ユーザー視点**で書かれている

## ステップ 3 — デザインシステム

- [ ] 新規コンポーネントに `.stories.tsx` が存在する（Storybook 使用時）
- [ ] UI ライブラリを直接編集していない
- [ ] 色はトークン指定（生の hex をハードコードしていない）
- [ ] グラデーション・装飾的 shadow は使用していない

## ステップ 4 — コピー・UX

- [ ] ユーザー向けテキストが規約に沿っている
- [ ] 絵文字の使用有無がプロジェクト規約に沿っている
- [ ] プロジェクト固有の禁止用語が含まれていない

## ステップ 5 — セキュリティ・PII

- [ ] 個人情報を不必要に扱う実装がない
- [ ] 環境変数がクライアント側で露出していない
- [ ] API ルートに適切な認証チェックがある
- [ ] 外部入力をサニタイズしている

## ステップ 6 — レビュー完了を記録（必須）

全ステップ通過後、Stop フックのブロックを解除するためにマーカーを置く。

```bash
touch /tmp/project-review-passed
```
